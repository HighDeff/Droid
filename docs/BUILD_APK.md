# Building & Installing the Droid APK

The Droid APK is a **remote controller** for the Droid backend. The automation
itself runs on the machine hosting the Node server (desktop via PyAutoGUI,
Android devices via ADB); the phone app is the control surface — live screen,
HUD buttons, AI planning, sequences.

## What you need

- The Droid backend running and reachable from the phone
  (`npm run build && npm start`, default port 3000).
- Node 20+ and the Android SDK (via Android Studio), **or** just Android
  Studio to open `android/` and build from the GUI.
- Java 17 (required by the Android Gradle plugin).

## 1. Start the backend (on your PC / server)

```bash
npm install
npm run build
npm start
```

Note the machine's LAN IP, e.g. `http://192.168.1.50:3000`.
The phone must be on the same network (Wi-Fi).

## 2. Sync the web UI into the Android project

```bash
npm run mobile:sync
```

This builds the React client into `dist/spa` and copies it into
`android/app/src/main/assets/public`.

## 3. Build the APK

Option A — Android Studio: open the `android/` folder, wait for Gradle sync,
then **Build → Build App Bundle(s) / APK(s) → Build APK(s)**.

Option B — command line (needs `ANDROID_HOME` set):

```bash
cd android
./gradlew assembleDebug
```

> **Note:** the binary `gradle-wrapper.jar` is intentionally not committed.
> If `./gradlew` complains about a missing wrapper jar, fetch it with:
> ```bash
> curl -L -o gradle/wrapper/gradle-wrapper.jar \
>   https://github.com/gradle/gradle/raw/master/gradle/wrapper/gradle-wrapper.jar
> ```
> (Or open the project in Android Studio, which handles the wrapper for you.)
> The launcher icons / splash PNGs under `android/app/src/main/res/` are also
> regenerated by `npx cap add android` — replace them with your own branding.

The APK lands at `android/app/build/outputs/apk/debug/app-debug.apk`.

## 4. Install on the phone

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Or copy the APK to the phone and tap it (allow "install unknown apps").

## 5. Point the app at your backend

Open the app → dashboard header → **Backend** control:

1. Type the server URL, e.g. `http://192.168.1.50:3000`
2. Tap **Save**, then **Test** — it should report "Connected ✓".

The URL is stored on-device, so you only do this once. (You can also bake
a default in at build time with `VITE_API_BASE_URL` in `.env`.)

## Release / signing

The debug APK is signed with the debug key and is fine for personal use.
For distribution, create a release keystore and add signing config in
`android/app/build.gradle`, then `./gradlew assembleRelease`.

## Troubleshooting

- **App shows the UI but every action fails**: the Backend URL is wrong or
  the server isn't reachable — use the **Test** button in the Backend control.
- **Cleartext HTTP blocked**: the manifest + `network_security_config.xml`
  already permit cleartext for LAN dev. For production, put the backend
  behind HTTPS and the app will use it automatically.
- **Desktop automation does nothing**: PyAutoGUI runs on the *server*
  machine — make sure `python-service/requirements.txt` is installed there
  and the server process has desktop access (not headless).
- **No Android devices listed**: run `adb devices` on the server machine;
  the grid shows real devices only (no more mock entries).

## What the APK does NOT do (yet)

On-device automation (an Android Accessibility Service that drives the
phone's own UI without a PC) is a separate native feature and is not part of
this build. The APK controls automation through the backend.
